원인 파악
현재 Vercel Serverless Function으로 배포된 api/faceswap.js 내부에서 수동으로 res.setHeader(...)를 통해 CORS 헤더를 설정하고 있었습니다. 하지만 Vercel의 경우, 다음과 같은 상황에서 Node.js 함수 내부로 진입하기 전에 Vercel Proxy/Edge 단에서 자체적으로 에러 처리를 하고 요청을 종료해 버립니다.

Preflight(OPTIONS) 요청에 포함된 특정 헤더가 허용되지 않았을 때
페이로드 크기 초과 에러(413 Error)가 발생했을 때
이때 Vercel Proxy 단에서 요청을 종료해버리면 api/faceswap.js의 코드가 실행되지 않으므로, 수동으로 설정한 Access-Control-Allow-Origin 헤더가 응답에 포함되지 않게 되고, 결과적으로 브라우저에서는 "CORS 에러"로 표시하게 됩니다.

해결 내용
vercel.json 글로벌 CORS 설정 적용: 함수 내부 코드가 아닌 Vercel 인프라 단에서 무조건 CORS 헤더를 달아서 응답하도록 /Source/vercel.json 및 최상단 디렉터리에 vercel.json을 수정하여 전역 CORS 설정을 추가했습니다.
Access-Control-Allow-Origin: *
다양한 메서드 및 인증 키(x-api-key) 등의 필수 헤더 허용 추가
api/faceswap.js 코드 정리: Vercel 인프라에서 전역으로 CORS 헤더를 달아주게 되었으므로, 자바스크립트 코드 내부에서 설정하던 중복/충돌되는 수동 헤더 설정 로직을 제거했습니다.
Preflight 요청 200 OK 복원: OPTIONS 요청이 들어왔을 때는 본문 검증을 건너뛰고 정상(200 OK)으로 응답하도록 분기 처리를 명확하게 유지했습니다.
Vercel 재배포 완료: npx vercel --prod 명령어를 통해 최신 수정본을 Vercel에 재배포 완료했습니다.
